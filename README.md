# Service Desk AI агент (прототип)

Санхүүгийн байгууллагын Service Desk-д ирсэн хүсэлтийг хүлээн авч, **ангилж** (төрөл / P1–P4 / баг),
**мэдлэгийн сангаар** (KB) хариулж, бусдыг нь **L2 багт тэмдэглэлтэйгээр шилжүүлж**, **тикет бүртгэж**,
P1 болон аюулгүй байдлын хүсэлтэд **нэн даруй мэдэгдэл** илгээдэг AI агент.

- **Python 3.13 + Streamlit**: вэб интерфейс (Streamlit Community Cloud дээр үнэгүй нийтийн URL)
- **Gemini API** (`gemini-3.1-flash-lite`, анхдагч) эсвэл **Claude API** (`LLM_PROVIDER`): structured output (Pydantic schema)
- **SQLite** (local) эсвэл **Postgres/Neon** (`DATABASE_URL`): тикет, мэдэгдэл, аудит лог, тохиргоо
- **Telegram Bot**: P1, Security, major incident, SLA сануулга

## Шалгагчид: хэрхэн турших вэ
1. Апп-ын URL-ийг нээж, **"Агент турших"** хуудсанд дурын мессеж бичнэ үү. Кирилл, латин монгол, англи хэл, нэг мессежид олон хүсэлт бичиж болно.
2. Үр дүнд төрөл, эрэмбэ, шийдвэр, баг, KB, хариу, L2 тэмдэглэл, нууцалсан PII, мэдэгдэл харагдана.
3. **Тикетүүд** хуудсанд бүх тикет, parent/child холбоос харагдана. Ажилтан эндээс шийдвэрийг засна (хүний хяналт).
4. **Тест (20 мессеж)** хуудсанд даалгаврын 20 тест мессежийн сүүлийн үр дүн, нарийвчлал (%) харагдана. Админ эндээс тестийг дахин ажиллуулж, тайланд оруулах хүснэгтийг татаж авна.
5. **Хяналт** хуудсанд kill switch (агентыг унтраах), Gemini загвар сонгох (өнөөдрийн хэрэглээ, төлөв), SLA явц, мэдэгдлүүд, injection/PII аудит лог байна.

## Local-д ажиллуулах
```bash
python3.13 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # GEMINI_API_KEY-ээ оруулна
streamlit run app.py                 # http://localhost:8501
pytest -q                            # API түлхүүргүй тестүүд (PII, injection, дүрэм, major incident)
python -m scripts.run_tests          # 20 тест мессеж → test-results.md
```

## Streamlit Community Cloud-д байршуулах
1. Кодоо GitHub руу push хийнэ.
2. https://share.streamlit.io → **Create app** → репо, `main` branch, `app.py`-г сонгоно. Advanced settings хэсгээс Python 3.13 сонгоно.
3. **Secrets** хэсэгт `.streamlit/secrets.toml.example`-ийн агуулгыг утгатай нь оруулна.
4. Cloud дээр SQLite файл апп дахин эхлэхэд арилдаг. Тиймээс тикетүүд хадгалагдах ёстой бол **Neon**-оос үнэгүй Postgres үүсгэж, `DATABASE_URL`-д оруулна. Хүснэгтүүд эхний хүсэлтээр автоматаар үүснэ.

## Архитектур
```
Мессеж (вэб форм / имэйл / chat / telegram)
  │
  ▼
[1] Kill switch шалгах ── унтраалттай → "ажилтан гараар шалгана"
  ▼
[2] PII mask (pii.py) ── регистр, утас, имэйл, дансыг [PHONE_1] гэх мэтээр солино
  ▼                       (LLM руу болон DB/лог руу зөвхөн нууцалсан текст очно)
[3] Injection guard (guard.py) ── regex: кирилл/латин/англи
  ▼
[4] LLM ангилал (classify.py) ── олон хүсэлт салгах, төрөл, нөлөө, яаралтай байдал,
  ▼                                  баг, entity, KB-д үндэслэсэн хариу, эрсдэлийн тэмдэглэгээ
[5] Дүрмийн давхарга (policy.py) ── LLM-ийг ДАРЖ хэрэгжинэ:
  │     injection → Татгалзах · фишинг/ransomware → P1 Security (KB-09)
  │     бусдын нууц үг → Татгалзах · хувийн мэдээллийн жагсаалт → Татгалзах
  │     эрх → KB-06 "Зөвшөөрөл хүлээж буй" (агент хэзээ ч эрх олгохгүй)
  │     KB-гүй "Хариулах" → Шилжүүлэх · KB-д байхгүй URL устгах
  │     P = нөлөө × яаралтай матриц (priority.py, кодоор)
  ▼
[6] Тикет хадгалах (db.py) + SLA хугацаа
  ▼
[7] Major incident (major_incident.py) ── 15 мин, нэг салбар, ≥3 ижил → parent P1
  ▼
[8] Мэдэгдэл (notify.py) ── P1 / Security / major incident → Telegram + бүртгэл
      SLA (sla.py) ── P1/P2 75%, P3 хэтэрсэн үед сануулга
```

## Таамаглалууд
- Даалгаварт **KB-05 байхгүй** тул зохиож нэмээгүй. Ноутбук удаан, техник хангамж, проектор зэрэг KB-гүй асуудлыг L1 ажилтанд шилжүүлнэ.
- Нууц үг мартсан тохиолдлыг хэрэглэгч өөрөө шийдэх боломжтой (SSPR) тул KB-01-ээр "Хариулах".
- Захирал/ТУЗ-ийн хэрэгцээг "удирдлага" буюу нөлөө Дунд гэж үнэлнэ.
- Хүсэлт гаргагч өөрийгөө "дарга", "IT-ийн ажилтан" гэж танилцуулсан ч баталгаажуулалт гэж үзэхгүй.
- P1/P2-ийн SLA-г 24/7, P3/P4-ийг ажлын өдрөөр (баярын өдөр тооцоогүй) тоолно.
- Injection илэрсэн мессежийг бүхэлд нь татгалзана (дотор нь хууль ёсны хүсэлт байсан ч).

## Хязгаарлалт
- Хэрэглэгчийн хэн болохыг (SSO/AD) бодитоор баталгаажуулдаггүй, зөвхөн мессежийн агуулгаар дүгнэнэ.
- Хавсралт (HR тойрох хуудас)-ыг уншдаггүй, ажилтан гараар шалгана.
- Тусдаа cron байхгүй тул SLA-г мессеж бүрийн дараа болон Хяналт хуудас нээгдэх бүрт шалгана.
- Rate limit нь хэрэглэгчийн session тус бүрд (минутад 15) ажилладаг.
- Gemini үнэгүй багц минутын/өдрийн квоттой тул 429 гарвал хүлээж дахин оролдоод, нөөц загвар руу шилжинэ. Шалгуулахад billing идэвхжүүлэхийг зөвлөнө.
- Хүсэлтийг вэб формоор хүлээн авна (3.1: аль нэг суваг хангалттай). Имэйл/Telegram webhook хэрэгжүүлээгүй.

## Бодит орчинд нэвтрүүлэхэд шаардлагатай
SSO (Google Workspace) нэвтрэлт, AD/Google Admin API-тай холбох (зөвхөн хүний баталгаажуулсны дараа), жинхэнэ
ticketing систем (Jira SM, GLPI г.м.), Gmail/Chat webhook, KB-г RAG болгох, LLM-ийн гаралтыг тогтмол үнэлэх eval
багц, өгөгдлийг дотоодод хадгалах (Монголбанкны шаардлага), DPA бүхий AI нийлүүлэгч.

## Аюулгүй байдал
- API түлхүүр зөвхөн `secrets.toml` эсвэл Cloud Secrets-д байна, репод ороогүй.
- Тикет болон лог-д зөвхөн нууцалсан текст хадгалагдана.
- Тикет засах, kill switch-д `ADMIN_PASSWORD` шаардана.
